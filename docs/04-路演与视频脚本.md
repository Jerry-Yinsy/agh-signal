# 演示视频与现场路演脚本

官方要求：提交 3–5 分钟演示视频（只交链接）；现场决赛 10/20 每队 5 分钟，其中 4 分钟路演 + 1 分钟提问，
须在 10/19 12:00 前提交 16:9 路演 PPT、主讲人信息与现场网络/设备需求。

## 一、演示视频分镜（目标 3 分 40 秒）

| 时间 | 画面 | 旁白要点 |
| --- | --- | --- |
| 0:00–0:25 | 校园/城区路口实拍或地图截图，标注早晚高峰方向不平衡 | 一个真实问题：路口配时靠人工试算，一轮几十分钟，而且常常只验证正常工况 |
| 0:25–0:50 | 展示 AGH 会话界面，输入任务 | 我们把这件事交给 AGH：它负责编排，工具负责算，证据自动留下 |
| 0:50–1:40 | 依次调用 traffic_scenarios、traffic_optimize（normal） | 6 个工况；寻优评估 835 个方案，不到 1 秒；车均延误从 22.0s 降到 16.7s |
| 1:40–2:20 | 展示报告截图：基线对比表 + Pareto 前沿 + 公平性方案 | 不只是"更快"，还给出效率与公平性的取舍 |
| 2:20–3:00 | 调用 traffic_optimize（peak / incident / oversaturated） | 基准配时在偏斜与事故工况失效，工具给出重新寻优收益；过饱和被明确拒绝并给降级建议 |
| 3:00–3:25 | artifacts/verification.md 滚动 | 5 项自动验证：自洽、与 Webster 交叉、复现性、边界、失败路径 |
| 3:25–3:40 | 收尾画面：工具链示意图 + 一句定位 | 把"寻优 + 边界验证 + 失败拒绝"做成可迁移的 Harness 范式 |

录屏要点：终端字号调大；命令提前打好只按回车；报告用编辑器打开而不是在终端里滚；
全程本地运行，不依赖外网。

## 二、现场 PPT 结构（16:9，共 8 页，对应 4 分钟）

| 页 | 内容 | 时长 |
| --- | --- | --- |
| 1 | 标题 + 一句话定位 + 团队与分工 | 15s |
| 2 | 问题：人工试算慢、只验证正常工况（配现场照片/流量数据来源） | 30s |
| 3 | 方案：AGH 编排 + 5 个工具 + 双层评估架构图 | 40s |
| 4 | 结果 1：normal 工况寻优，22.0s → 16.7s，评估 835 个方案 | 35s |
| 5 | 结果 2：Pareto 与公平性方案（平均延误 +1.4% 换最差进口延误 −14%） | 30s |
| 6 | 结果 3：边界工况（偏斜、事故降容）与失败拒绝（过饱和） | 40s |
| 7 | 验证：5 项检查 + SUMO 对照表 + 复现方式（seed、命令、哈希） | 30s |
| 8 | 价值与后续：可迁移到其它工程仿真；局限与下一步 | 20s |

提问环节预案（1 分钟，通常 1–2 个问题）：

- **"你们的模型准不准？"** 答：我们定位是快速筛选，最终方案由 SUMO 复核；两者差异在验证报告里有逐工况对照表，口径差异也解释了。
- **"和 Webster 公式比有什么新东西？"** 答：Webster 只给一个方案，我们做的是闭环：自动寻优 + 边界工况批量验证 + 失败显式拒绝 + 可复现证据，并且能在 AGH 上被 Agent 直接调用。
- **"为什么周期只有 60s？"** 答：该工况总流率比 Y≈0.60，Webster 最优周期本来就在下限附近；我们在报告里同时给出了更长周期的备选与公平性方案。
- **"能不能直接下发到信号机？"** 答：目前只输出建议与证据，不下发；对接真实信号机属于后续工作。

## 四、现场风险预案

1. 演示机器准备好离线环境：AGH 与项目全部本地运行，不依赖外网；提前 `daemon stop` 再 `serve` 热身。
2. 关键命令提前写进 run-demo.ps1，现场只按一次回车，避免手打出错。
3. 报告与验证结果提前生成好放在 artifacts，网络再差也能翻文件讲解。
4. 录屏兜底：视频文件放在本机，PPT 里留一页备用的结果截图。
