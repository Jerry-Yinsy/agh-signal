## 三、落地步骤

### 1. 拷到 D 盘

解压 `agh-signal-package.zip` 或直接复制目录，目标是 `D:\dev\agnes-project\agh-signal`。

### 2. 先跑通（不依赖 AGH，也不依赖网络）

```powershell
Set-Location 'D:\dev\agnes-project\agh-signal'
node src\cli.mjs selfcheck                    # 各工况最优配时一览
node src\cli.mjs report --scenario normal     # 生成寻优报告与验证报告
node tools\plugin-selftest.mjs                # 插件免模型自检
.\run-demo.ps1                                # 等价的一键流程
```

### 3. 接入 AGH

```powershell
Set-Location 'D:\dev\agnes-project\agnes-harness'
$env:AGH_HOME = 'D:\dev\agnes-project\agh-home'
$env:AGNES_PROFILE = 'local-dev'
$env:AGH_SIGNAL_HOME = 'D:\dev\agnes-project\agh-signal'
node .\packages\cli\dist\local\agnes.mjs daemon stop
node .\packages\cli\dist\local\agnes.mjs serve
```

关键点：`AGH_SIGNAL_HOME` 必须对 daemon 进程可见，所以要在启动会话里设置并重启后台；
插件靠这个变量定位 `src/cli.mjs`。

然后在另一个终端按 docs/02 第三节执行 `package inspect` → `install` → `package trust` →
`package enable` → `package status`（trust 或 enable 的失败原因会直接显示，按提示重取 integrity 即可）。
装完不用重启，新能力在轮次边界生效。

### 4. 产生运行证据

按 docs/02 第五节的 6 步提示词在同一个 AGH 会话里依次跑：看工况 → 寻优 → 边界复核 →
失败路径 → 出报告 → SUMO 交叉验证。每步的调用参数、返回 JSON 和你的判断都会留在会话记录里，
可直接作为提交要的"AGH 执行记录 + 工具调用链 + Agnes 模型参与核心任务证据"。

## 四、还需要你这边确认的两件事

### 1. SUMO 相位映射（唯一没在本机验证的部分）

项目里的 SUMO 适配层（路网生成、车流生成、相位映射、tripinfo 指标解析、缺失时自动降级）已经写好，
但这台机器没装 SUMO，我无法验证"相位映射是否对得上你的路网"。请按 docs/03 第二节核对一次：

```powershell
node src\cli.mjs sumo-check
node src\cli.mjs sumo-sim --scenario normal --cycle 70 --green-ns 34
node src\cli.mjs sumo-map
```

如果相位顺序不是默认约定，用 `$env:SIGNAL_LOOP_PHASE_GROUPS = 'EW,NS'` 覆盖后重跑。
装不上也不影响主流程：其余命令照常工作，只是少了微观仿真这条交叉验证证据（需在作品说明里如实写明）。

### 2. 数据口径

工况里的流量目前是占位数（总需求约 2580 辆/小时），饱和流率用经验值。按排期在 10/6–10/7
换成公开流量数据或你们实地计数，并在作品说明里标注数据来源——这一项直接关系到
"问题价值与学科融合"那 20%。
